이 절차를 담은 작은 Skill 전체

Skill은 특정 업무의 수행 지침과 필요한 지원 파일을 묶어 재사용하는 단위입니다. 중심 파일인 SKILL.md에는 사용 시점을 설명하는 정보와 실제 수행 방법이 함께 들어갑니다.

아래는 시연에서 읽는 파일 전체입니다. 앞에서 한 판단이 입력·절차·완료 기준으로 옮겨졌습니다.

주간업무 보고서 초안

다른 종류의 요청에 이 분류·서식을 강제로 적용하지 않는다.

입력

사용자가 지정한 보고 기간과 기준일, 업무표, 관련 회의 메모.

같은 파일 · 이어서

절차

1. 보고 기간과 기준일을 확인하고 지정한 자료를 읽는다.

2. 업무표에서 확인한 상태를 완료·진행·막힘으로 분류한다.

3. 각 주장 옆에 자료 이름과 행 또는 문단 위치를 남긴다.

4. 자료가 없으면 해당 정보만 미확인으로 남긴다. 확인한 사실은 유지한다.

5. 상태가 상충하면 두 근거와 확인할 사항을 남기고 한 상태로 확정 집계하지 않는다.

6. 분류·근거 확인 후 assets/report-template.md의 빈 서식을 읽고 초안을 작성한다.

7. 기간·상태·근거·누락 표시를 원자료와 대조해 초안을 제시한다.

완료 기준

완료·진행·막힘 및 다음 확인 항목이 있다. 각 업무 주장에 근거가 있고,

확인하지 않은 상태나 일정을 만들어 넣지 않았다.

읽기 요청과 돌아온 내용은 다른 증거입니다

Tool call은 파일 읽기나 검색 같은 구체 행동을 도구에 요청하는 호출입니다. 앱이 도구를 실행하고 결과를 돌려주면 에이전트는 그 내용을 다음 판단에 사용할 수 있습니다.

이 시연에서는 Skill·서식·원자료의 읽기와 반환된 실제 텍스트를 확인한 뒤 초안을 봅니다. 파일 경로가 보이는 것과 내용을 성공적으로 읽은 것은 다릅니다.

  1. 주간보고서 범위·자료 읽기·분류·근거·누락·서식·대조 기준 확인

  2. 완료·진행·막힘 각 1건과 11월 5일 검토 예정의 원문 확인

  3. 업무표 세 행과 회의 메모 1항을 결과 주장에 대응

  4. 정답이 없는 서식의 제목·필드·구역 확인

  5. 기간·세 업무 상태·검토 일정·근거를 대조하고 오탈자 1곳 수정

자료가 같아도 요청의 목적이 다를 수 있습니다

옆 사람과 초안을 바꾸거나 스스로 처음 읽는 사람처럼 검토하세요. 입력을 어디서 얻는지, 판단 기준이 무엇인지, 결과가 맞는지 확인할 방법이 보이는지 살펴봅니다.

수업 뒤에는 작성한 Skill에 정상 입력과 정보가 하나 빠진 입력을 넣어 결과를 비교해 보세요. 읽기 성공과 지침 적용은 각각 확인하고, 기대 결과를 모델 입력에 넣지 않습니다.
